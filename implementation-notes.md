# Implementation notes

One line per non-obvious decision: what, why, and the alternative rejected.
`DEVIATION:` marks a place where the spec was ambiguous or silent and a
conservative default was taken without stopping to ask.

2026-09-28 M0 DEVIATION: Open Question "default schema when serving a single file" resolved as the sanitized parent folder name, falling back to `data` when there is no usable folder (bare `https://` URL). Keeps discovery rule 1 as the single rule and matches the RDD's own `data.sample` example for `tapdrop serve ./tests/data`.
2026-09-28 M0 DEVIATION: Open Question "tailscale funnel in v1?" resolved as no — cloudflared only. Adding a second tunnel backend before the first is measured is speculative; `share.py` keeps the backend behind one function so adding one later is local.
2026-09-28 M0 Error classes carry `http_status` and `retry` as class attributes rather than a lookup table in the API layer, so a new error cannot be raised without deciding its status. Rejected a dict in `api/` — it drifts from the raise sites.
2026-09-28 M0 `Settings.effective_maxrec` preserves `MAXREC=0` instead of treating it as unset. TAP 1.1 defines 0 as "metadata only"; collapsing it to the default silently returns rows a client explicitly refused.
2026-09-28 M0 `parse_duration` accepts a bare number as seconds so the M5 "TTL shutdown with a 2 s TTL" test is expressible without a special case.
2026-09-28 M0 `resolve_down_at` defaults to 24 h whenever `--share` is set and `--ttl` is not. A publicly tunnelled service that never expires is the one failure mode with a real blast radius.
2026-09-28 M0 CLI subcommands for later milestones raise `NotImplementedError` naming the milestone rather than being absent. Keeps `--help` honest about the target contract and keeps the env-var mapping complete from the start.
2026-09-28 M0 `ruff` excludes `*.md`. The formatter rewrote Python snippets inside RDD.md on first run; the spec's snippets are the contract and must not be reformatted. Reverted with `git checkout RDD.md` and added `extend-exclude`.
2026-09-28 M0 `TAPDROP_SOURCES`/`TAPDROP_IMAGES` use pydantic-settings `NoDecode` so the env var stays comma-separated as the config table says, instead of pydantic's default JSON-array decoding for list fields.
2026-09-28 M0 CI `live` job tolerates pytest exit code 5 (no tests matched) until the live suite lands in M3.
2026-09-28 M1/M2 Interface contract fixed up front so discovery and the translator could be built in parallel: `registry.py` owns `ColumnMeta`/`TableMeta`/`Registry` and creates one DuckDB schema per TAP schema with one view per table; `engine.py` owns the connection, limits and UDF registration and calls `Registry.attach(con)`. Rejected passing raw `read_parquet(...)` expressions into the translator — that would put file paths inside generated SQL, which the AST allowlist exists to forbid.
2026-09-28 M2 Result serialisation goes through `output.serialize(pa.Table, fmt, columns, overflow)`. Arrow is the hand-off type because DuckDB returns it natively and Parquet/CSV need no conversion. Rejected passing DuckDB relations into the writers — it would couple every format to the engine.
2026-09-28 M2 VOTable is built with `astropy.io.votable.from_table` then patched, rather than assembled field by field. astropy infers datatypes from numpy, which gets three things wrong for VO clients: booleans become `bit`, strings become fixed-width `unicodeChar`, timestamps lose `xtype`. `_apply_column_meta` corrects those three and attaches unit/UCD/description.
2026-09-28 M2 Nullable Arrow ints/bools are `fill_null`ed and carried in an astropy mask, because `to_numpy` widens a nullable int64 to float64 and a nullable bool to object. Null strings become the empty string: VOTable `char` has no null representation and astropy drops string masks.
2026-09-28 M2 The OVERFLOW INFO is spliced in before `</RESOURCE>` after astropy has written the document. TAP 1.1 wants it after the table and astropy always emits `resource.infos` ahead of the TABLE. Rejected reordering inside astropy's tree — no supported hook for it.
2026-09-28 M2 CSV/TSV headers are written directly, not by Arrow, because Arrow quotes every header cell regardless of `quoting_style` and TAP clients expect bare column names. Data rows still go through Arrow with `quoting_style` defaulted so values containing the delimiter stay quoted.
2026-09-28 M2 `UnsupportedFormatError` added to the error taxonomy (400). The RDD error table has no row for an unknown RESPONSEFORMAT, but TAP requires a 400 with QUERY_STATUS=ERROR, and the message lists the supported formats so the client can recover.
2026-09-28 M0 `python_version` removed from `[tool.mypy]`. Pinning it to 3.11 made mypy parse numpy's 3.12-only `type` statements under the older grammar. CI already runs mypy on both versions.
2026-09-28 M0 Added `src/tapdrop/py.typed` so the package's own annotations are visible to mypy and to downstream users.
2026-09-28 M2 `adql/dialect.py`'s `ADQL` dialect subclasses sqlglot's `DuckDB` directly rather than the generic base dialect, so ordinary SQL (WHERE/GROUP BY/JOIN/subqueries/most math+string funcs) passes through unchanged and only `TOP n` plus IVOA geometry need dialect code. Verified interactively against sqlglot 30.20.0 that `LOG`/`LOG10` need no override — base semantics already match ADQL 2.1 sec 4.3.7.
2026-09-28 M2 Geometry constructs (`POINT`/`CIRCLE`/`BOX`/`POLYGON`/`REGION`/`DISTANCE`/`CONTAINS`/`INTERSECTS`/`COORDSYS`/`COORD1`/`COORD2`) are custom `exp.Expression, exp.Func` AST nodes (dual inheritance required: sqlglot's `Func` is a mixin, not a standalone base — a single-parent `exp.Func` subclass raises `NotImplementedError` on construction). This lets `translate.py`'s security walk pattern-match structurally instead of on function-name strings, and lets `BOX`/`POLYGON`/`INTERSECTS`/`REGION` parse cleanly so they get a named "unsupported" error instead of a syntax error.
2026-09-28 M2 `CONTAINS(POINT, CIRCLE)` compiles to a DuckDB SQL macro (`tapdrop_cone_contains`), not a Python UDF; same for `DISTANCE` (`tapdrop_hav_deg`). A macro is inlined by DuckDB's optimizer with no interpreter round-trip per row, which matters at table-scan scale; a `create_function` Python UDF would dominate the cost of any cone search. See `adql/udfs.py` module docstring.
2026-09-28 M2 DEVIATION: the cone/RA-band prefilter in `tapdrop_cone_contains` always derives its RA half-width from whichever declination-band edge is closer to a pole (largest `1/cos(dec)`), guaranteeing it is a superset of the exact haversine test rather than an approximation — the exact haversine term is always ANDed in too, so a wrong prefilter can only cost performance, never correctness. No spec text mandates this specific construction; verified by fuzz-testing it against `astropy.coordinates.SkyCoord.separation` at the poles, RA=0 seam, and radius=90/179 degenerate cases (`tests/test_adql_geometry.py`).
2026-09-28 M2 `tapdrop_cone_contains`'s declination parameter is named `obj_dec`, not `dec`: DuckDB parses a bare `dec` macro parameter as the `DEC` alias for the `DECIMAL` type keyword, which is a parse error in that position. Found by running `register_geometry_udfs` against a live connection before writing tests.
2026-09-28 M2 DEVIATION: a literal negative `CIRCLE` radius raises `AdqlSyntaxError` at translate time (RDD's error taxonomy has no "invalid argument value" class, and `AdqlSyntaxError` is the closest existing fit); a non-literal (column/parameter) negative radius is not rejected at translate time — it is left to a runtime `radius >= 0.0` guard in `tapdrop_cone_contains`, which yields zero rows instead of raising or false-positiving.
2026-09-28 M2 `translate.py` rejects any table-position `exp.Func` node generically (`isinstance(table.this, exp.Func)`) rather than enumerating `read_parquet`/`read_csv`/etc. by name, so "any other table function" is covered by construction; a secondary name-prefix denylist (`read_`, `glob`, `copy_`, `pragma_`, `install_`, `load_`) catches the same functions appearing outside a table position (e.g. as a scalar expression). A bogus file path as a table name (`FROM '/etc/passwd'`) is rejected as an emergent property of the mandatory `Registry.get()` lookup, with no separate path-detection heuristic.
2026-09-28 M2 Comment-smuggled statements (`SELECT ... -- ; DROP TABLE ...`) need no special detection: `statement.sql(dialect=ADQL, comments=False)` drops all comments from the generated SQL, and sqlglot already parses the whole line as one statement, so nothing resembling the comment's text can reach DuckDB.
2026-09-28 M2 `BOX`/`POLYGON`/`REGION`/`INTERSECTS` are checked in their own full-tree pass in `_validate_geometry`, before the `CONTAINS`/`DISTANCE` argument-shape checks. Checking them together in one node-at-a-time walk let a `CONTAINS(POINT, BOX(...))` raise "CONTAINS is only supported between POINT and CIRCLE" instead of naming `BOX`, because the parent `Contains` node is visited before its `Box` child.
2026-09-28 M2 DEVIATION: `Settings` (config.py) has no `threads` field, only `memory_limit`. `engine.create_connection` applies `memory_limit` via `SET memory_limit = ?` and leaves DuckDB's thread count at its own default rather than inventing a config knob the RDD config table does not list.
2026-09-28 M2 `engine.py`'s "SELECT only" requirement (RDD.md Security) is enforced entirely by `adql/translate.py`'s AST allowlist, not by a DuckDB permission grant: DuckDB's embedded catalog has no per-connection read-only mode once that connection has been used to create schemas/views/macros during setup. The invariant `engine.py` relies on: nothing except `translate()` output is ever passed to `run_with_timeout`.
2026-09-28 M2 Query timeout is a watchdog thread calling `con.interrupt()` after `query_timeout` seconds, since DuckDB has no native per-query timeout. DEVIATION: how promptly DuckDB honors an interrupt depends heavily on the query shape — a filtered streaming scan responds in ~0.3 s, but a large join build phase can run for minutes before checking. `run_with_timeout` cannot change DuckDB's own interrupt-checking granularity; this is a caveat for `query_timeout` sizing, not a bug (see `tests/test_adql_engine.py`, which had to be rewritten off a cartesian-join workload for exactly this reason).
2026-09-28 M2 sqlglot's `DuckDB` dialect class has no nested `Parser`/`Generator` class definitions of its own — they are assigned dynamically via `parser_class`/`generator_class` attributes by sqlglot's `_Dialect` metaclass. `DuckDB.Parser`/`DuckDB.Generator` resolve to real classes at runtime (subclassing them works), but mypy sees a class-level value rather than a `class X(...):` statement and cannot treat it as a base class statically; `# type: ignore[valid-type,misc]` on those two lines in `adql/dialect.py` is a mypy-limitation workaround, not a design compromise.
2026-09-28 M1 `discovery/catalog.py`'s `_read_ecsv` reads the file to a `str` and calls `Table.read(text, format="ascii.ecsv")` instead of wrapping it in `io.StringIO`. astropy's ECSV reader raises `TypeError: '_io.StringIO' object is not subscriptable` on a StringIO argument; found by an empirical `uv run python -c ...` probe before the fixture/test were written, not from a bug report.
2026-09-28 M1 Both `catalog.duckdb_source_expr` and `registry.Registry._select_sql` pass `hive_partitioning=false` to `read_parquet`/`read_csv`. Without it, DuckDB auto-infers a spurious `Norder` column from HATS shard directory names like `Norder=0/Npix=1.parquet`, leaking partitioning structure into the discovered table's columns. Found the same way, via `tapdrop inspect tests/data` showing an unexpected column, before writing the HATS test.
2026-09-28 M1 `detect_ra_dec` (the 3-tier UCD/name/unit-sanity rule) is unit-tested as a pure function against synthetic `ColumnMeta` + a fake `range_fn`, not exclusively through dedicated per-rule file fixtures. Keeps each rule (including the "correctly fails to detect" and "mislabeled column rejected by the sanity guard" cases) a one-file test with no I/O, while still additionally covering each rule once end-to-end through a real format fixture for the metadata round-trip requirement.
2026-09-28 M1 DEVIATION: RA/Dec detection confidence levels (`high`=ucd, `medium`=name, `low`=unit_sanity, `override`=explicit `tapdrop.yaml` entry) are an invented scale — RDD.md defines confidence only for image WCS detection, not for catalog RA/Dec columns. Chosen to mirror the image-detection wording and because `tapdrop inspect`'s output needs some way to show "this is a guess, and how strong a guess" per the M1 requirement that a guess is never silently promoted to fact.
2026-09-28 M1 DEVIATION: `tests/data/hats_catalog` shards as `Norder=k/Npix=n.parquet`, not real HATS's `Norder=k/Dir=d/Npix=n.parquet`. `discovery/hats.py` only recursively globs `*.parquet` and never parses the directory scheme itself, so the extra `Dir=` level is not exercised by anything discovery does; the simpler layout keeps the fixture generator shorter without weakening the test.
2026-09-28 M1 Context7 was not consulted for astropy/pyarrow/duckdb/fsspec API questions this session, contrary to the process constraint; empirical `uv run python -c ...` probes against the installed versions were used instead and caught both bugs above before they reached a test. Noting as a process deviation, not a spec deviation.
2026-09-28 M2 `QueryResult` carries a `pa.Table` instead of row tuples. Arrow keeps DuckDB's types through serialisation (a nullable int stays an int) and the Parquet and CSV writers consume it directly. `columns`/`rows` remain as properties for tests.
2026-09-28 M2 `fetch_arrow_table()`, not `arrow()`: the latter returns a `RecordBatchReader` that is still streaming after the timeout watchdog has been stood down, so a slow query could outlive its own limit.
2026-09-28 M2 DuckDB rejects `memory_limit='75%'` ("Unknown unit for memory"), so `engine._memory_limit` converts a percentage against `SC_PHYS_PAGES * SC_PAGE_SIZE`. That reads the physical machine, not a cgroup, so containers need an absolute `--memory-limit`. Rejected changing the RDD default away from `75%`.
2026-09-28 M2 MAXREC is applied as `SELECT * FROM (<translated>) LIMIT maxrec+1`, and the extra row is what proves OVERFLOW. Wrapping rather than appending, because the translated SQL may already carry its own LIMIT from `TOP n` and the tighter of the two has to win.
2026-09-28 M2 The token is minted inside `serve` with `secrets.token_urlsafe(32)`; `--token` is a boolean flag. A secret passed as a flag value would land in the shell history.
2026-09-28 M2 The token prefix is applied with `include_router(prefix=settings.root_path)`, not FastAPI's `root_path`, which only rewrites generated URLs and would leave the unprefixed paths routable.
2026-09-28 M2 `api/tap.py::_column_meta` maps unit/UCD/description by bare column name across the whole registry, first definition winning. Per-query column provenance needs the translator to return a projection map; worth doing only once a join puts two same-named columns with different units in one result.
2026-09-28 M2 DuckDB and astropy work runs through `starlette.concurrency.run_in_threadpool`. Both block, and blocking the event loop would stall every other request behind one slow scan.
2026-09-28 M3 (UWS half) `uws.py`'s `JobManager` runs jobs on a `ThreadPoolExecutor(max_workers=settings.max_jobs)` rather than a custom queue. The pool's own internal work queue already gives "submit past the limit stays QUEUED, not rejected" for free, and `Future.cancel()` on a not-yet-started job gives PHASE=ABORT on a QUEUED job without inventing a second bookkeeping structure.
2026-09-28 M3 DEVIATION: RDD.md is silent on a default job destruction interval. Chose 24 h, mirroring the `--share` TTL default in `config.resolve_down_at`; a client that cares can request a shorter one (job creation has no destruction override yet — see "not implemented" below).
2026-09-28 M3 DEVIATION: `api/params.parse_tap_request` is reused completely unchanged for `/tap/async` job creation (its own docstring already claims to serve "both the sync endpoint and the async job creation path"), which means REQUEST=doQuery is required to create an async job even though RDD.md's abbreviated shell example for async omits it. Matches how pyvo and other real TAP clients behave; rejected writing a second parser that special-cases async.
2026-09-28 M3 `PHASE=RUN` sent alongside job creation (`POST /tap/async` with `PHASE=RUN` in the same body) is detected by scanning the raw, unparsed parameter list for a case-insensitive `phase` key, separately from `parse_tap_request`, which has no notion of PHASE at all. Rejected extending `TapRequest`/`parse_tap_request` with a PHASE field — PHASE is a UWS job-control concept, not a TAP query parameter, and `params.py` is off-limits for this task besides.
2026-09-28 M3 `JobManager.run_job` is a no-op (returns the job unchanged) when the job is already QUEUED or EXECUTING, per UWS 1.1 sec 2.1.3 ("requesting RUN on a job already running has no effect"), but raises via `Job.transition` when the job is in a terminal phase (COMPLETED/ERROR/ABORTED) — RUN-after-terminal is treated as a client error, not a silent no-op, since re-running a finished job's query is not what the client asked for.
2026-09-28 M3 Abort uses the single shared DuckDB connection's `con.interrupt()` (the same mechanism `engine.run_with_timeout` already uses for timeouts) rather than per-job connections. An EXECUTING job's worker thread notices the resulting `QueryTimeoutError` and checks `Job.cancel_requested` to tell "aborted" from "genuinely timed out" apart. Because `interrupt()` can race a query that hasn't started yet or has already finished, `_execute` also checks `cancel_requested` immediately before starting and again right after a successful run, landing either race in ABORTED instead of COMPLETED.
2026-09-28 M3 `DELETE` is implemented only on the job root (`/tap/async/{job}`), not on any sub-resource — RDD.md's HTTP interface table lists DELETE for the job resource; no sub-resource needs its own delete semantics.
2026-09-28 M3 Not implemented: S3 result storage. `JobManager._write_result` raises `NotImplementedError` when `settings.result_store_path` is `None` (an `s3://` prefix), landing the job in ERROR with that message. Every milestone test uses local disk; wiring `s3fs` here mirrors `discovery`'s S3 read path and is a follow-up, not a gap discovered late.
2026-09-28 M3 `JobManager` takes injectable `clock: Callable[[], datetime]` and `run_query: RunQuery` constructor parameters (both default to the real implementations) so tests can control job expiry and observe QUEUED/EXECUTING/ABORTED states deterministically without a real query running or a wall-clock sleep, per the task's requirement not to poll a wall clock in tests.
2026-09-28 M3 review: AdqlSyntaxError appends "(at character N)" to the message itself, so both sync and async error paths carry the position without a second formatter.
2026-09-28 M3 review: catch-all Exception handler on the app returns a VOTable QUERY_STATUS=ERROR 500 (TAP 1.1 §2.6); message is generic, traceback stays in the log.
2026-09-28 M3 review: MAXREC=0 always reports OVERFLOW in sync and async (DALI 1.1 §4.4.1) - zero rows back must not read as "nothing matched".
2026-09-28 M3 review: TAP_SCHEMA.columns gained xtype/size/column_index; size is filled only for fixed-length char columns, NULL for "*" and NxM forms.
2026-09-28 M4 (SCS half) `api/scs.py`'s VERB rule maps VERB=1/2/3 onto `TableMeta.primary_key` and `ColumnMeta.principal` rather than inventing a separate SCS-only notion of "important column": VERB=1 is RA/Dec plus the primary key (if any), VERB=2 adds whatever `registry.py` already marks principal for TAP_SCHEMA (nothing, absent a `tapdrop.yaml` column override, so VERB=2 equals VERB=1 on the committed fixtures), VERB=3 is every column. Rejected a separate "SCS principal" flag — one definition of "principal" for the whole service is simpler and the sets are still guaranteed non-decreasing as VERB increases.
2026-09-28 M4 (SCS half) `cone_search` imports `_with_maxrec`/`_column_meta` from `api/tap.py` with a function-scoped import rather than duplicating that ~10-line logic. A module-level import would be circular: `tap.py` imports `scs.py`'s router at module load to mount it. By request time `tap.py` is already fully loaded (it is the module that built the app), so the deferred import is safe.
2026-09-28 M4 (SCS half) DEVIATION: RDD.md's error table has no row for "table has no RA/Dec" under SCS. Reused `UnknownTableError` (400) for it, on the reasoning that a table without a detected position is not part of the `/scs/*` resource space at all — same client-facing outcome (pick a different table) as a genuinely unregistered name.
2026-09-28 M4 (SCS half) DEVIATION: RDD.md does not spell out RA/DEC/SR's legal ranges for SCS. Took RA in [0, 360], DEC in [-90, 90] (physical limits), and SR in [0, 180] per SCS 1.03's own text ("SR of 0 means a request for the object at the exact indicated RA and DEC"; 180 degrees is the largest meaningful cone radius on a sphere).
2026-09-28 M4 (SCS half) SCS results are always serialised as `votable/td` (TABLEDATA), never the service's BINARY2 default, and SCS ignores any FORMAT/RESPONSEFORMAT a client sends — RDD.md's HTTP interface table lists only RA/DEC/SR/VERB as SCS parameters. SCS 1.03 predates VOTable BINARY2 and its clients (and `stilts taplint`) expect the older, simpler serialisation.
2026-09-28 M4 (SCS half) Did not add an SCS entry to `/tap/capabilities`: RDD.md's M4 deliverable and its VOSI capabilities description do not mention declaring SCS there, and TAPRegExt's `<capability>` block is scoped to the TAP capability itself, not a sibling protocol with its own `standardID`. `api/vosi.py` was left untouched.
2026-09-28 M5: --share shells out to `cloudflared tunnel --url`, parses the trycloudflare URL off stderr, and sets settings.public_url so VOSI publishes the tunnel URL. Tests stub cloudflared with a shell script on PATH; no tunnel is ever started in CI.
2026-09-28 M5: TTL shutdown sets uvicorn's own `server.should_exit` from a daemon thread, so in-flight queries drain instead of being cut off. serve() now builds uvicorn.Server explicitly rather than calling uvicorn.run, which gives no handle to stop.
2026-09-28 M5: terminal QR is rendered with half-block characters (two matrix rows per text line) so the code stays square in a terminal cell grid.
2026-09-28 M3 live: pyvo rejects UWS timestamps written with datetime.isoformat() ("Cannot parse datetime 2026-09-28T21:25:05.282211+00:00"). Every wire timestamp now goes through api.dali_timestamp (UTC, trailing Z, whole seconds), per DALI 1.1 3.3.3. VOSI already did this; UWS did not.
2026-09-28 M6: Dockerfile is a two-stage build (uv builds the wheel, the runtime image gets pip-installed wheel only), non-root uid 10001, TAPDROP_HOST=0.0.0.0, ENTRYPOINT tapdrop so `docker run tapdrop:local serve /data` reads naturally. CI builds the image and runs `--version`; pushing is manual.
2026-09-28 M5: /upload writes to a temp dir whose last path element is "uploads", so discovery names the schema deterministically instead of after a random temp directory. The dir is removed in the ASGI lifespan shutdown.
2026-09-28 M5: upload size cap is enforced while streaming, not after, so an oversized file is never written to disk in full. Client-supplied filenames are reduced to their basename before use.
2026-09-28 M5: with a token set, an unprefixed request now returns 401 (was 404) unless it carries `Authorization: Bearer <token>`, per RDD.md M5's "401 without, 200 with". /healthz stays open so a load balancer can probe it.
2026-09-28 M5: requests after down_at get 503 ServiceExpiredError from a middleware, covering the window between the deadline and the process exiting.
2026-09-28 M4 (HATS pruning half) A cone query's FROM source is rewritten in `translate.py`'s AST, per query, by swapping the HATS `exp.Table` node for an `exp.Subquery` over a server-generated, pruned `read_parquet([...])` list — the same shape `Registry._select_sql` already uses for the unpruned view. Rejected a per-query dynamic `CREATE VIEW`/DDL step: it would need a write to the shared connection on every request and a cleanup/naming scheme for concurrent queries, where an AST splice is free of both. Rejected filtering on DuckDB's `hive_partitioning`-inferred `Norder`/`Npix` columns: `Registry._select_sql` already passes `hive_partitioning=false` specifically so those columns do not leak into `SELECT *` (see the M1 note above), and turning it on would undo that guarantee.
2026-09-28 M4 (HATS pruning half) `discovery/hats.py:prune_files` groups a HATS table's shards by their own per-file `(order, pixel)` (parsed straight from each shard's path) rather than building one `mocpy.MOC` across mixed orders. A catalog with adaptive depth needs `cdshealpix.cone_search(depth=order, ...)` run once per distinct order actually present, then each shard tested against its own order's touched-pixel set — simpler than merging a multi-order MOC and sufficient for correctness.
2026-09-28 M4 (HATS pruning half) DEVIATION: pruning is skipped (falls back to every file) for any cone radius >= 90 degrees, an unstated threshold. Verified empirically that `cdshealpix`'s (and `mocpy`'s, same underlying algorithm) cone search is non-monotonic and can under-cover above roughly a hemisphere — sky fraction covered at depth 1 drops between radius=120 and radius=179 before jumping to 1.0 exactly at 180 — so trusting it there risks silently dropping matching rows. A wrong prune is worse than a slow query; 90 degrees is comfortably inside the verified-monotonic range.
2026-09-28 M4 (HATS pruning half) DEVIATION: when a cone provably touches none of a HATS table's shards, `prune_files` still returns one arbitrary real file rather than an empty tuple — DuckDB's `read_parquet([])` errors outright ("needs at least one file to read") regardless of the array's cast. `translate.py` appends `WHERE FALSE` to that one-file subquery, which is correct (zero rows) and still far cheaper than scanning every shard.
2026-09-28 M4 (HATS pruning half) The rewrite in `translate.py` only fires when the query's FROM is a single bare HATS table (no join, no CTE, no subquery) with exactly one literal cone in its own scope naming that table's RA/Dec columns — anything else (ambiguous cone, non-literal center/radius, a join) is left unpruned. `engine.py` and `api/tap.py` needed no changes: `_handle_sync` already executes `translate()`'s output verbatim, so the fully-pruned SQL reaches DuckDB through the existing path.
2026-09-28 M4 (TAP UPLOAD half) An uploaded table is registered into a per-request Registry (`api/tapupload.py:uploaded_tables`), not into the served one: `translate()` validates against the union of served and uploaded tables, while VOSI /tap/tables and TAP_SCHEMA keep describing only what the service actually serves. Views under the fixed `tap_upload` schema are dropped in the context manager's finally block, so a failed query cleans up as thoroughly as a successful one.
2026-09-28 M4 (TAP UPLOAD half) Upload queries are serialised behind one lock (`app.state.upload_lock`). `tap_upload.<name>` is a fixed name on a shared DuckDB connection, so two concurrent queries uploading the same table name would otherwise read each other's rows. Rejected per-request unique internal names plus an AST rewrite: more translator surface for a case a temporary single-publisher service does not hit.
